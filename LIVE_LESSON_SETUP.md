# MedStart Live: подключение видеосервера

## Что уже находится в проекте

- защищённый серверный маршрут `/api/livekit/token`;
- серверный маршрут `/api/livekit/status`, который не раскрывает ключи и
  сообщает клиенту, готов ли собственный видеоконтур;
- проверка Firebase ID Token;
- допуск только студента и репетитора из подтверждённой онлайн-записи;
- отдельная комната `medstart_<bookingId>` для каждого занятия;
- три честно разделённых режима: видео, только голос и доска без звонка;
- живой предпросмотр, индикатор микрофона и выбор камеры/микрофона до входа;
- адаптивное видео 720p с simulcast и dynacast;
- автоматические попытки переподключения;
- камера, микрофон, демонстрация экрана и поднятие руки;
- быстрый режим «только голос и доска»;
- совместная векторная доска и чат;
- короткие realtime-пакеты штрихов через LiveKit, рассчитанные на слабую сеть;
- настоящие локальные GLB-модели HRA/NIH с резервной SVG-проекцией без WebGL;
- долговременное сохранение доски в Firestore;
- локальная копия доски и очередь Firestore при временной потере сети.

Кнопка занятия не имитирует звонок. Пока сервер не подключён, видео и голос
помечаются как недоступные, а медицинская доска открывается отдельным режимом
без загрузки LiveKit-клиента.

## Обязательные Secrets

В Replit должны быть добавлены:

```text
MEDSTART_LIVE_VIDEO_ENABLED=true
LIVEKIT_URL=wss://rtc.<домен MedStart>
LIVEKIT_API_KEY=<ключ собственного LiveKit>
LIVEKIT_API_SECRET=<секрет собственного LiveKit>
```

Пока собственный сервер не развёрнут и не проверен, используйте:

```text
MEDSTART_LIVE_VIDEO_ENABLED=false
```

Одного флага `true` недостаточно: MedStart включает кнопки видео и голоса только
при одновременно заданных `LIVEKIT_URL`, `LIVEKIT_API_KEY` и
`LIVEKIT_API_SECRET`. URL должен начинаться с `wss://`. Маршрут статуса также
делает короткий авторизованный запрос к Room Service: при неверных ключах,
таймауте или недоступном сервере кнопки звонка не включаются.

Для безопасной проверки Firebase пользователя серверу также нужен один secret:

```text
FIREBASE_SERVICE_ACCOUNT_JSON=<полный JSON service account одной строкой>
```

Вместо одного JSON поддерживаются отдельные:

```text
FIREBASE_ADMIN_PROJECT_ID
FIREBASE_ADMIN_CLIENT_EMAIL
FIREBASE_ADMIN_PRIVATE_KEY
```

API secret LiveKit и приватный ключ Firebase нельзя помещать в переменные с
префиксом `NEXT_PUBLIC_`, отправлять в чат или хранить в исходниках.

## Почему доска не отправляет штрих одним большим сообщением

LiveKit рекомендует удерживать lossy-пакет примерно в пределах 1300 байт, а
reliable-пакет — в пределах 15 КиБ. Поэтому MedStart:

- во время рисования не чаще одного раза в 50 мс отправляет lossy-снимок штриха
  максимум из 24 равномерно выбранных точек;
- после отпускания пера отправляет reliable-версию максимум из 200 точек;
- проверяет тему пакета, размер, структуру и UID отправителя;
- сохраняет полный элемент в Firestore как долговременную версию;
- после подключения загружает последние 1200 элементов и сортирует их по времени.

Так второй участник видит линию ещё во время рисования, а при потере data packet
доска восстанавливается из Firestore.

Официальное описание ограничений:
https://docs.livekit.io/transport/data/packets/

## 3D-анатомия

Модели сердца, дыхательной системы, печени, правой почки и женского таза хранятся
в проекте в формате GLB и загружаются только после открытия анатомического
модуля. Просмотрщик также хранится локально, поэтому runtime не зависит от
внешнего CDN. Для устройств без WebGL автоматически используется облегчённая
схематическая проекция.

Источник моделей — Human Reference Atlas / HuBMAP, лицензия CC BY 4.0. Точные
исходные файлы и атрибуция перечислены в
`artifacts/medstart/public/models/anatomy/ATTRIBUTION.md`.

## Рекомендуемый production-контур

Для выполнения требования «работает в России без VPN» не использовать LiveKit
Cloud. Развернуть open-source LiveKit Server на собственной инфраструктуре в
российском дата-центре.

Минимальный первый запуск:

1. отдельная VM с публичным IPv4 для LiveKit;
2. домен `rtc.<домен>` и действующий TLS-сертификат;
3. WebSocket/API через TCP 443;
4. WebRTC UDP;
5. WebRTC TCP 7881;
6. TURN/UDP;
7. TURN/TLS, доступный пользователю снаружи на TCP 443;
8. Redis — сразу, если планируется второй узел и автоматическое резервирование.

Для TURN/TLS на 443 используйте конфигурацию, которую создаёт официальный
генератор LiveKit. Если TURN работает без L4-балансировщика,
`turn.tls_port` должен быть равен `443`, потому что именно этот порт сервер
сообщает клиентам. Для нескольких узлов нужен сетевой L4-балансировщик и
отдельная проверка его TLS/NAT-схемы.

Официальный генератор конфигурации и VM-инструкция LiveKit предпочтительнее
самописного Docker Compose: WebRTC требует корректно сообщать внешний IP,
открывать UDP и выпускать сертификаты.

- VM-развёртывание: https://docs.livekit.io/transport/self-hosting/vm/
- порты и firewall: https://docs.livekit.io/transport/self-hosting/ports-firewall/
- TURN/TLS и production-конфигурация:
  https://docs.livekit.io/transport/self-hosting/deployment/

## Порты, которые проверяются перед запуском

| Назначение          |                     Внешний порт |
| ------------------- | -------------------------------: |
| HTTPS/WSS сигналинг |                          TCP 443 |
| WebRTC через TCP    |                         TCP 7881 |
| WebRTC через UDP    | UDP 50000–60000 или UDP mux 7882 |
| TURN/UDP            |      UDP 3478 и резервно UDP 443 |
| TURN/TLS            |    TCP 443 через отдельный IP/L4 |

## Публикация правил данных

Новая доска использует:

```text
whiteboards/{bookingId}/elements/{elementId}
```

После загрузки проекта необходимо опубликовать новые правила:

```bash
npx firebase-tools deploy --only firestore,storage
```

Без этих правил видеосвязь сможет подключиться, но сохранение доски будет
отклоняться Firestore.

## Контрольный тест

1. Создать онлайн-заявку студента.
2. Принять её репетитором.
3. Открыть одну и ту же запись на двух устройствах.
4. На обоих устройствах выбрать камеру/микрофон и проверить предпросмотр.
5. Войти первым устройством с камерой, вторым — «только голос и доска».
6. Проверить звук в обе стороны.
7. Включить и выключить камеру.
8. Проверить демонстрацию экрана с ПК.
9. Нарисовать, добавить фигуру и текст с обоих устройств.
10. Нарисовать один непрерывный длинный штрих в течение 20–30 секунд и
    убедиться, что второй участник видит его до конца.
11. Открыть все пять 3D-моделей, проверить вращение, масштаб и перенос проекции
    на доску.
12. Обновить страницу и убедиться, что доска восстановилась.
13. Заблокировать UDP в тестовой сети и проверить TURN/TLS.
14. Переключиться между Wi‑Fi и мобильной сетью во время звонка.
15. Отключить интернет, нарисовать штрих, вернуть сеть и проверить
    синхронизацию.

## Критерий готовности

Публичный запуск видеозанятий разрешён только после успешного теста с двух
разных операторов связи, проверки TCP/TURN fallback и мониторинга не менее
одной недели. Запуск только по успешному звонку внутри одной Wi‑Fi сети не
считается проверкой production-связи.
