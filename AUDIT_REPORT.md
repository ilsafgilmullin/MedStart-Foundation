# MedStart 5.0 — онлайн-занятие, устойчивый клиент и учебная база

## v5 — учебная материальная база

- Добавлен общий раздел `/dashboard/knowledge`.
- Встроен стартовый каталог официальных ресурсов Минздрава России, ФЭМБ,
  ГРЛС, ФМЗА и ВОЗ.
- Разделены официальные источники, проверенные материалы репетиторов и личные
  материалы занятия.
- Добавлены поиск, фильтры по дисциплине/типу/уровню и синхронизируемое
  избранное.
- Активный репетитор может предложить HTTPS-ссылку или PDF до 25 МБ.
- Добавлены подтверждения медицинской тематики, прав на публикацию и
  отсутствия данных пациентов.
- Материал скрыт от студентов до ручного одобрения.
- Владелец и администратор получили очередь модерации с причиной отклонения.
- Клиент не может присвоить материалу официальный статус или самостоятельно
  опубликовать его.
- Добавлены Firestore и Storage Rules для публикаций, файлов и закладок.

## Продуктовая модель

MedStart — маркетплейс медицинских репетиторов, а не LMS. В проекте нет
фиктивных курсов, тестов, сертификатов и прогресса. Основной контур:

`каталог → профиль репетитора → заявка → подтверждение → MedStart Live → материалы`

Общий учебный контур работает рядом с занятием:

`официальные источники → поиск → избранное → публикация репетитора → модерация`

Роли Firestore: `student`, `tutor`, `admin`. Владелец определяется по
закреплённому Firebase UID и получает эффективную роль `owner`.

## Реализовано

### Общая платформа

- отдельная регистрация студента и репетитора;
- Email/Password Firebase Authentication;
- восстановление пароля и повторная отправка подтверждения почты;
- защита кабинета от отсутствующего, заблокированного и удалённого профиля;
- разная навигация и главная страница для студента, репетитора и владельца;
- единый адаптивный интерфейс для ПК и телефона;
- реальные показатели вместо демонстрационных чисел.

### MedStart Live — сердце продукта

- собственная полноэкранная комната занятия без ссылки на Zoom;
- защищённая серверная выдача короткоживущего токена;
- повторная проверка Firebase ID Token и конкретной записи;
- блокировка входа в комнату для заблокированного или удалённого аккаунта;
- доступ только студента и репетитора подтверждённого онлайн-занятия;
- камера, микрофон, демонстрация экрана и поднятие руки;
- адаптивные слои 720p, simulcast и dynacast;
- повторные попытки WebRTC/WebSocket соединения;
- быстрый переход на режим «только голос и доска»;
- отдельная адаптивная компоновка для телефона и ПК;
- совместная векторная доска: перо, маркер, ластик, линии, фигуры и текст;
- отмена/повтор, экспорт PNG и очистка репетитором;
- realtime-синхронизация доски по каналу комнаты;
- живые штрихи разбиваются на MTU-безопасные порции, а итоговый штрих повторно
  передаётся надёжными чанками;
- долговременное сохранение и восстановление через Firestore;
- локальный кэш доски и очередь изменений при кратком обрыве;
- встроенный чат занятия с сохранением переписки.
- отдельная кнопка разблокировки звука, когда Safari/iPhone запрещает autoplay.

### Скорость и повторное открытие

- видеодвижок загружается только на маршруте конкретного занятия;
- Firebase Storage вынесен из общего стартового пакета;
- убрана runtime-зависимость от Google Fonts;
- ролевые маршруты предварительно загружаются после входа;
- предварительная загрузка выполняется во время простоя браузера и не включается
  при `Save-Data`/2G;
- добавлены мгновенные loading-состояния;
- Service Worker кэширует только публичную оболочку и статические файлы;
- приватные страницы кабинета не складываются в общий HTTP-кэш;
- Firestore использует постоянный локальный кэш с поддержкой нескольких вкладок.
- расписание рассчитывается в сохранённом часовом поясе занятия.
- удалён оставшийся неиспользуемый контур Google Sign-In.
- стандартная предзагрузка ссылок отключена; управляемая предзагрузка остаётся
  только для нормальной связи, поэтому новый раздел не расходует трафик на
  `Save-Data`/2G;
- модуль чтения Firebase Storage для PDF загружается только по действию
  пользователя.

### Репетитор

- модерация `pending → active/rejected`;
- редактирование полной анкеты;
- загрузка фотографии с телефона в Firebase Storage;
- специализация, предметы, вуз, опыт, город, цена, длительность и формат;
- повторная отправка отклонённой анкеты;
- входящие заявки студентов;
- принятие, отклонение и завершение занятия;
- рабочие часы по дням недели;
- расписание подтверждённых занятий;
- список реальных студентов;
- личные диалоги;
- материалы для конкретного студента.

### Студент

- каталог только одобренных публичных репетиторов;
- поиск по имени, предмету, вузу и городу;
- отдельная карточка репетитора;
- просмотр обычных рабочих часов;
- заявка с темой, целью, датой, временем и форматом;
- статусы заявки и ответ репетитора;
- отмена текущей записи;
- расписание и история;
- чат с репетитором;
- просмотр полученных материалов.

### Владелец и администратор

- UID владельца закреплён;
- модерация репетиторов с причиной отклонения;
- реальные показатели пользователей;
- поиск по пользователям;
- блокировка и восстановление аккаунтов;
- назначение и снятие роли администратора владельцем;
- защита владельца от блокировки и смены роли;
- автоматическое исправление ошибочного имени владельца «Олег» на «Ильсаф».

### Безопасность данных

- пользователь не может самостоятельно изменить роль, статус, рейтинг и
  публичность;
- заявку создаёт только активный студент к активному публичному репетитору;
- статус занятия меняют только его участники по разрешённым переходам;
- чаты и сообщения видны только двум участникам и модераторам;
- рабочие часы редактирует только сам репетитор;
- реквизиты квалификации вынесены из публичного профиля в отдельный закрытый
  документ;
- материал создаёт только репетитор подтверждённого занятия;
- публикацию в общей учебной базе создаёт только активный репетитор;
- неопубликованный ресурс видят только автор и модератор;
- репетитор не может сам присвоить статус `published` или официальную отметку;
- PDF ограничен размером, MIME-типом, сигнатурой и защищён отдельными Storage
  Rules;
- личное избранное доступно только владельцу аккаунта;
- фотографию профиля загружает только владелец аккаунта;
- правила Firestore и Storage находятся в корне проекта.

## Для включения требуется инфраструктура

Интерфейс и защищённый серверный контур видеозанятия реализованы, но настоящий
звонок не включается без собственного LiveKit/SFU. Необходимы:

- российская VM/кластер LiveKit;
- WSS, WebRTC UDP/TCP, TURN/UDP и TURN/TLS;
- `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`;
- серверный Firebase service account;
- публикация новых правил Firestore.

Остальные отдельные production-функции:

- платежи и возвраты;
- автоматические email/push-уведомления;
- отзывы с доверенным пересчётом рейтинга;
- серверный антивирус и карантин PDF перед медицинской модерацией;
- лицензированный полнотекстовый фонд учебников;
- Firebase custom claims и серверные административные операции.

Текущий Firebase/Replit-контур остаётся переходным риском для требования полной
независимости от зарубежной инфраструктуры. План миграции находится в
`ARCHITECTURE_RU_RESILIENCE.md`.
