# MedStart V6 — профессиональная медицинская доска

## Цель

V6 превращает обычный canvas в клиническое рабочее пространство внутри
MedStart Live. Видео, голос, чат, классическая доска и медицинские объекты
остаются в одной комнате занятия.

## Реализованный вертикальный срез

### Диагностические изображения

- PNG, JPEG и WebP до 25 МБ;
- выбор модальности: рентген, КТ, МРТ, УЗИ, фото, другое;
- повторное кодирование изображения в WebP внутри браузера;
- исходный файл не загружается;
- EXIF и контейнерные метаданные отбрасываются;
- опциональная чёрная маска на верхние 14% кадра;
- ручное подтверждение отсутствия идентификаторов пациента;
- хранение в отдельном контуре `lesson-assets/{bookingId}/{uid}`;
- доступ разрешён только участникам подтверждённого занятия и модераторам.

Исходные DICOM-файлы в первом срезе намеренно не принимаются. DICOM может
содержать идентификаторы не только в видимом заголовке, но и в тегах, private
attributes, overlays, burned-in annotations и связанных сериях. До появления
серверного DICOM de-identification gateway пользователь должен экспортировать
обезличенный кадр из диагностического просмотрщика.

### Анатомия

- встроенные слои для пяти систем организма;
- проекции спереди, сзади, слева и справа;
- интерактивный поворот;
- наложение поверх доски;
- отсутствие внешних CDN и runtime-зависимостей.

Текущий слой является автономным векторным 3D-контуром. Реалистичный атлас
GLTF/DRACO должен подключаться только после проверки лицензий, медицинской
точности моделей и размещения ассетов в собственном хранилище MedStart.

### Клинические шаблоны

Фиксированная структура:

1. жалоба;
2. анамнез;
3. осмотр;
4. рабочий диагноз;
5. план.

Шаблон создаётся как перемещаемый объект поверх доски. Он предназначен для
учебного разбора и не заменяет медицинскую документацию.

### Лабораторные данные

- до 12 показателей в одном объекте;
- значение, единицы измерения и референс;
- флаги normal / low / high / critical;
- поле интерпретации;
- табличное представление на доске.

### ЭКГ и кривые

- учебные пресеты синусового ритма, ФП, СВТ, ЖТ и асистолии;
- регулируемая ЧСС;
- кардиографическая сетка;
- комментарий преподавателя;
- обязательная маркировка «учебная модель, не для диагностики».

### Синхронизация

Медицинские объекты синхронизируются через отдельный надёжный LiveKit Data
Channel `medstart.medical-board.v1`:

- upsert и удаление объектов;
- запрос полного snapshot при подключении;
- tutor-authoritative snapshot для поздно подключившегося участника;
- локальный кэш на случай кратковременного обрыва;
- право репетитора удалить любой объект;
- студент может удалить только созданный им объект.

Классические штрихи продолжают использовать существующий канал доски и
Firestore. Разделение протоколов не позволяет крупным клиническим объектам
ухудшить отзывчивость пера.

## Модель безопасности

V6 реализует техническое обезличивание, но не обещает автоматическую
анонимизацию любых клинических данных. Перед загрузкой пользователь обязан
проверить:

- ФИО;
- дату рождения;
- адрес и телефон;
- номер полиса и медицинской карты;
- штрихкоды и QR-коды;
- лицо пациента;
- нанесённые идентификаторы в любом участке снимка.

Перед production-запуском необходимо заменить Firebase download-token URL на
авторизованную выдачу blobs через внутренний API MedStart или собственное S3 с
короткоживущими подписанными URL. Текущая реализация подходит для закрытого
MVP, но не должна использоваться для персональных медицинских данных.

## Следующие обязательные этапы V6

1. DICOM gateway: tag allowlist, profile-based de-identification, burned-in
   annotation detection, audit trail и карантин исходника.
2. Серийный просмотр: window/level, zoom, pan, cine, измерения, MPR.
3. Локальный лицензированный 3D-атлас GLTF/DRACO с анатомическими labels.
4. Серверное долговременное хранение медицинских объектов и версий доски.
5. Экспорт занятия: PDF-конспект, снимки, клинический шаблон, лаборатория и
   журнал действий.
6. Интеграции с PACS/MIS только через DICOMweb/FHIR gateway и отдельный контур
   согласий; прямые клиентские подключения запрещены.
7. Полный отказ от Firebase в production-контуре РФ согласно
   `ARCHITECTURE_RU_RESILIENCE.md`.
